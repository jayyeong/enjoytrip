# 콘텐츠 기반 여행지 추천

## 서비스

기존 Java KMP 검색·병합 정렬에 추가한 세 번째 알고리즘이다. 추천 받기를 누르면 선택 지역·시군구에서 선호 유형과 담은 장소 유형별 최근 수정 후보를 최대 100곳씩 별도로 조회한다. 지도에 표시된 장소 및 이름 검색 결과와 독립적이며, 전국을 선택하면 전국 API 후보를 조회한다. 전국 전체를 전수 비교하는 방식은 아니다. 조회 대상 총수·실제 후보 수·추천 수를 구분해 표시한다. 점수 계산은 브라우저 JavaScript에서 실행하고 최대 3/5/10곳을 추천한다. 현재 여행에 담은 장소는 제외한다.

## 알고리즘과 점수

관광지·숙박·음식점·문화시설·축제·여행코스·쇼핑·레포츠의 8차원 유형 벡터를 사용한다. 후보 장소는 자신의 유형 차원만 1인 one-hot 벡터다. 사용자 벡터의 유형 t 가중치는 다음과 같다.

`p[t] = 3 × (명시적으로 선택했으면 1, 아니면 0) + 2 × (현재 여행의 t 유형 개수 / 유효 유형 장소 개수)`

현재 여행에 같은 ID가 중복되어도 한 번만 센다. 명시적 선택을 현재 담은 목록보다 우선하도록 가중치를 3과 2로 정했다. 학습된 파라미터가 아니라 설명 가능한 기획상의 값이다. 코사인 유사도는 `p[t] / sqrt(sum(p[i]^2))`이다. 화면의 취향 일치도는 이 값을 100배 한 것이며 만족 확률·평점·방문 인기도가 아니다.

양수 점수 후보만 내림차순으로 정렬하고 동점은 원본 입력 순서를 유지한다. 이미 담은 ID, 중복 후보 ID, ID 없는 후보, 알려지지 않은 유형은 제외한다. 취향도 담은 장소도 없다면 추천을 꾸며내지 않고 유형 선택을 안내한다. 같은 유형 후보끼리는 점수가 같다는 한계가 있다. 지역·거리·가격·다른 사용자 행동은 점수에 사용하지 않는다.

## 자료구조와 복잡도

유형 가중치 Map, 담은 ID와 중복 방지 Set, 점수 배열을 사용한다. 후보 N, 담은 장소 R, 유형 차원 D=8일 때 시간 O(R+D+N log N), 추가 공간 O(R+D+N)이다. 코사인 계산은 one-hot 특성을 이용해 후보당 O(1)이다. 결과 제한만 10개이며 정렬은 양수 점수 후보 전체에 수행한다.

## 화면 연동 및 검증

추천 이유에 선택한 유형·담은 동일 유형 개수를 표시한다. 상세보기와 여행에 추가는 기존 기능을 호출한다. 유형 변경·목록 갱신·여행 변경 시 추천 결과를 비워 과거 결과를 재사용하지 않도록 한다. 선호 선택은 페이지 메모리에 보관한다. 후보 조회에는 선택 지역과 관광 유형 코드가 관광정보 API로 전달되며, 사용자 계정이나 여행계획 전체는 전송하지 않는다. 일부 유형 조회가 실패하면 성공한 후보로 추천하고 경고를 표시한다. 모두 실패하면 재시도를 안내한다. 요청 중 지역·유형·여행 구성이 바뀌면 이전 응답은 무시한다.

`npm test`에 추천 검사 212개를 추가했다. 취향 없는 시작, 명시적 선호, 담은 장소의 유형 반영 및 제외, 중복, 알 수 없는 유형, 결과 개수, 점수 범위와 100가지 입력 크기의 기준 순서를 검증한다. 브라우저에서는 취향 없는 안내, 문화시설+음식점 선택 시 박물관과 한식당 추천 및 각각의 이유 표시를 확인했다.

소스: `js/recommendation.js`, `js/recommendation-ui.js`, `js/recommendation-candidates.js`. 후보 조회 범위·중복 제거·부분 실패·전체 실패·샘플 모드는 `scripts/recommendation-candidates-test.mjs`로 추가 검증한다. 테스트: `scripts/recommendation-test.mjs`.

이전 버전 운영 검증(24개 목록을 사용하던 버전): 실데이터에서 문화시설 선택 시 가가책방·가나아트센터의 취향 일치도 100.0과 추천 이유를 확인했다. 앞의 박물관·한식당 사례는 로컬 샘플 검증이다. [운영 캡처](screenshots/production-recommendation.png).


## UX 개선 반영

로그인 없이 여행 초안을 구성할 수 있어 담은 유형 분포를 즉시 추천에 활용한다. 초안은 현재 브라우저에 보관되며 다른 기기에 동기화되지 않는다. 후보 조회는 60초·64건 한도의 메모리 캐시와 동시 요청 합치기를 사용한다. 점수식과 유형별 최대 100곳 조회 상한은 동일하다.
