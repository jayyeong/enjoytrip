# 검증 결과

검증일: 2026-10-02

로컬 서버 `python run.py`와 실제 Microsoft Edge headless 브라우저(Playwright)로 화면 및 사용자 흐름을 확인했습니다.

## 통과한 항목

- 첫 화면 로드, API 실패 안내와 샘플 관광정보 14건 표시
- 회원가입, 로그인/로그아웃, 회원정보 수정
- 아이디/이메일 확인 후 비밀번호 재설정 및 새 비밀번호 로그인
- 회원 탈퇴와 저장된 회원정보 삭제
- 지역·문화시설 유형 필터, 결과 없는 검색
- 관광지 여행 추가, 방문 순서 변경
- 날짜/경비를 포함한 여행계획 저장 및 저장 목록 표시
- Hotplace 사진 포함 등록·목록·삭제
- 게시글 등록·상세·수정
- 공지 등록·상세·수정·삭제
- 데스크톱(1440px) 및 모바일(390px) 레이아웃 확인
- 모바일 document 너비가 viewport를 넘지 않음
- 검증 중 브라우저 JavaScript 런타임 오류 0건
- JavaScript 문법 검사 통과

## 실시간 연동의 한계

현재 환경의 실제 요청은 공공데이터 API 및 카카오 지도 SDK 연결 실패 상태였습니다. 실시간 장소 조회·시군구 데이터·지도 마커·현재 위치 검색은 외부 서비스의 유효한 키와 도메인, 브라우저 위치 권한이 있는 환경에서 별도 확인해야 합니다. 실패 시 화면이 멈추지 않고 샘플 목록, 지도 연결 안내, 외부 지도 링크를 제공함을 확인했습니다. 추가 기능 검증에서는 외부 요청을 실패시키고 샘플 데이터를 사용했습니다.

Windows Python 기본 HTTP 서버가 `.js`를 `text/plain`으로 전달하는 문제를 발견해 `run.py`에서 JavaScript MIME 형식을 지정했습니다.

## 디자인 변경 검증

KUAD 레퍼런스 디자인 적용 후 기존 브라우저 사용자 흐름을 다시 실행해 통과했습니다. 회원가입/로그인/정보수정, 여행계획 저장, 게시글 수정, 유형 필터/빈 결과, 방문 순서 변경, 사진 포함 Hotplace 등록·삭제, 공지 CRUD, 비밀번호 재설정, 탈퇴를 확인했습니다. 모바일 390px에서 가로 넘침 및 런타임 오류가 없었으며, 메인 이미지 내 제목 크기도 모바일 너비에 맞췄습니다.

Fafter/KUAD를 참고해 장식 문구, 이미지 위 대형 제목, 반복 설명, 샘플 카드의 장식 썸네일을 제거한 미니멀 디자인으로 수정했습니다. 기존 회원/계획/커뮤니티 브라우저 흐름과 모바일 390px 검증을 다시 통과했습니다.

## 2026-10-02 실시간 API 연결 검증

- 카카오 지도 사용 활성화 및 배포/localhost 도메인 등록 완료, 로컬과 운영 지도 타일 렌더링 확인.
- KorService2 인증키는 로컬 제외 파일과 Cloudflare 환경 변수에 설정. Git에 키 값은 저장하지 않음.
- areaBasedList2(서울), ldongCode2(서울 시군구), searchKeyword2(경복궁), detailCommon2 실응답 검증.
- 브라우저에서 시군구 옵션 갱신, 경복궁 검색 및 상세 설명 표시 확인.
- 지역 선택은 삭제 예정 areaCode2 대신 법정동 시도/시군구 코드 사용.
- 위치 검색은 locationBasedList2, 유형 필터는 contentTypeId 사용. 행사/숙박 전용 검색, 상세 소개/반복/추가 이미지/반려동물 정보는 현재 미구현.

## UX 점검 및 개선 (2026-10-02)

기획서 F101~F103(지역·유형 조회), F104(여행계획), F107~F108(회원), NF101~NF104(직관성·반응형·응답성·정확성)를 기준으로 사용 흐름을 점검했습니다.

- 로그인/가입을 마친 뒤 직전에 선택한 장소 추가를 이어서 실행.
- 선택 장소의 ‘추가됨’ 표시와 나의 여행 장소 수, 여행계획으로 이동할 링크 제공.
- 회원별 여행 초안 및 입력값을 브라우저에 보관하고 새로고침/재로그인 후 복원.
- 불러온 계획은 수정 저장하며 중복 계획 생성 방지. 새 계획은 별도 동작으로 제공.
- 지역 선택 전 시군구 비활성화, 조회 중/실패 안내, 검색조건 요약과 초기화 제공.
- 추가 페이지 조회는 최초 검색/위치 조건 유지. 추가 조회 실패 시 기존 결과 보존.
- 장소 이름 선택 시 해당 위치로 지도 이동. 상세정보의 이전 응답이 다른 모달을 덮어쓰지 않도록 처리.
- 모바일 상단 이미지 높이 축소, 터치 대상 확대, 키보드 포커스와 현재 메뉴 표시 개선.

검증: 임시 브라우저 프로필에서 가입 후 장소 추가, 초안 복원, 중복 없는 수정 저장, 재로그인 복원, 종속 필터 및 초기화, 390px 화면 넘침/런타임 오류 없음 확인. 기존 유형 필터/빈 결과/경로 순서/Hotplace 사진 등록·삭제/공지 CRUD/비밀번호 재설정/탈퇴 회귀 검증 통과. npm run build 통과.

프론트엔드 학습용 범위: 회원·계획·글은 이 브라우저에 저장되며 서버 계정/다른 기기 동기화는 구현하지 않았습니다. F106 뉴스 크롤링은 미구현입니다.

## 전체 페이지 디자인과 찜 기능 (2026-10-02)

여행지·찜·계획·핫플·이야기·공지·내 정보 7개 페이지를 데스크톱 1280px 및 모바일 390px에서 점검했습니다. 버튼·입력창·모달 선택창·글꼴·여백·포커스를 공통 스타일로 정리했습니다.

찜은 로그인 없이 이 브라우저에 저장/복원/해제하며 카드 및 상세창에 선택 상태가 표시됩니다. 찜 목록에서 계획에 추가하거나 핫플 등록을 시작할 수 있습니다. 로그인 필요 시 등록 흐름을 이어가며 장소명·주소·오늘 날짜를 자동 입력하고 사진과 소개는 선택사항입니다.

검증: 찜 새로고침 유지/해제, 로그인 후 핫플 자동 입력 및 등록, 전체 7개 페이지에서 가로 넘침/런타임 오류 없음, 기존 UX와 회원·게시판·Hotplace 회귀 테스트 및 빌드 통과.

## 지도 중심 메인 (2026-10-02)

메인을 상단 유형 메뉴, 왼쪽 검색·장소 목록, 오른쪽 지도 구조로 변경했습니다. 모바일에서는 지도 위/결과 아래로 분할하고 조건은 접었다 펼칩니다. 큰 소개 이미지 대신 바로 지도 탐색을 시작하며, 목록 내부 스크롤로 지도 위치를 유지합니다. 유형 선택 즉시 검색, 마커 클릭 상세 연결, 지도 크기 변경 시 relayout을 적용했습니다.

실제 API로 검색·유형 변경·찜·페이지 이동·모바일 조건/상세창 검증, 7개 페이지의 데스크톱/모바일 레이아웃 및 회원·핫플·공지 회귀 검증을 통과했습니다.

## 본문 게시판 화면 (2026-10-02)

Fafter 게시판을 참고해 여행 이야기와 공지의 상세/작성/수정을 모달에서 본문 화면으로 변경했습니다. 목록의 글 제목은 링크이며 글 URL(#board/id 또는 #notice/id)로 새로고침/뒤로가기/직접 접근이 가능합니다. 목록 검색어는 상세 진입 후에도 유지됩니다. 작성자에게만 수정·삭제를 제공하고 삭제된 글 주소는 목록으로 돌아갈 수 있도록 안내합니다.

임시 브라우저에서 글/공지 CRUD, URL 새로고침·브라우저 뒤로가기, 삭제된 글 접근, 모바일 화면 넘침 없음, 본문 화면에서 모달 없이 동작하는 것과 빌드를 검증했습니다.
